# OutStake Yield Adapters

## 文档目的

本文档汇总当前 upgradeable SY adapter 的统一行为和产品边界。

## 统一规则

- 所有 SY adapters 都通过 `SYBaseUpgradeable` 提供的 proxy-backed 抽象实现
- 所有 adapter 都保留 `deposit`、`redeem`、`previewDeposit`、`previewRedeem`、`exchangeRate`、`getTokensIn`、`getTokensOut`
- 跨 adapter 的 SY 单位契约以 `docs/spec/common-foundations.md` 的「单位模型」为准：`SYBaseUpgradeable.sol::__SYBase_init` 绑定 yield-bearing token decimals，`SYBaseUpgradeable.sol::deposit` 将 `SYBaseUpgradeable.sol::_deposit` 返回值直接作为 `_mint` 数量，因此 1 SY unit 等于对应 yield-bearing-token domain 的 1 unit；Aave 族使用 `scaledBalanceOf` 的 scaled-share domain，而非随流动性指数增长的 nominal balance domain
- oracle-backed variants 通过 `exchangeRateOracle` storage 获取汇率
- adapter 本身不重复继承 UUPS
- `SYBaseUpgradeable.sol::deposit` 与 `SYBaseUpgradeable.sol::redeem` 均挂 `nonReentrant`（`ReentrancyGuardTransient` 经 `TokenHelper`）：`deposit` 隔离 `_transferIn` 与 adapter `_deposit` 外调窗口内对 `deposit`/`redeem` 的重入，`redeem` 保护 token-out-before-burn 逆CEI顺序的 `_redeem` 外调窗口。`redeem` 采用 token-out-before-burn 结算顺序：adapter `_redeem`（含外部调用）先把 tokenOut 交付给 receiver，随后 `_burn` 才烧掉 SY 份额；`burnFromInternalBalance=true` 仅允许 owner 配置的 trusted router caller 使用，并从 `address(this)` 烧份额；其他 caller 传入 `true` 会回退。`burnFromInternalBalance=false` 仍是直兑路径，从 `msg.sender` 烧份额。这条 CEI 逆序是有意设计，调整顺序或移除 `nonReentrant` 前必须保留该不变量。
- 消费外部协议的 `_redeem` 路径不得以常驻授权暴露 yield-bearing-token 背书：`OutrunL2StakedUsdsSYUpgradeable.sol::_redeem` 在 PSM3 swap 腿以逐笔精确 `_safeApprove` 授权同 call 将被 `transferFrom` 拉走的数量（外部协议按 `amountIn` 接口语义足额拉取时，残余 allowance 为 0）；不使用常驻无限授权（惰性刷新到 max 的授权语义会把常驻背书置于无限授权下，外部协议沦陷即单笔抽空）。Sky L2 的 `_deposit` PSM3 swap 腿同样以逐笔精确 `_safeApprove` 授权中转输入 token（差额守卫见 `PSM3IncompleteConsumption`）；其余族 `_deposit` 外部拉款腿（`OutrunWstETHSYUpgradeable` 的 stETH wrap 腿、`OutrunStakedUSDeSYUpgradeable` 与 `OutrunStakedUsdsSYUpgradeable` 的 4626 deposit 腿、`OutrunAaveV3SYUpgradeable` 的 pool supply 腿、`OutrunAsBNBSYUpgradeable` 的 slisBNB mint 腿、`OutrunWeETHSYUpgradeable` 的 eETH wrap 腿）同样以逐笔精确 `_safeApprove` 授权本次拉取额，外部协议按接口契约足额拉取时调用返回后残余 allowance 为 0（AsBNB 腿另经 `AsBnbMintIncompleteConsumption` 强制全量消费，Sky L2 腿经 `PSM3IncompleteConsumption`），不设常驻授权；venue 违反接口契约部分拉取且不回退时残余 allowance 有界（≤本次存款批准额），且经下次存款的 `forceApprove` 设置语义（设置而非增量）覆写清除、不跨存款累积——误转滞留的中转 token 对沦陷 spender 不可达（此前六族 deposit 腿经常驻无限授权的缺口就此关闭）。

## SY 错误面与初始化约束

本节列出 `SYBaseUpgradeable` 和各 adapter 自身声明的自定义错误，供集成方建立 selector、触发条件和重试分支矩阵。`TokenHelper`、OpenZeppelin 以及外部协议产生的错误属于依赖边界，不在下表的 SY/adapter 自定义错误全集内。

### SYBase 错误

| 错误 | 入口 | 触发条件 |
| --- | --- | --- |
| `SYInvalidTokenIn(address token)` | `SYBaseUpgradeable.sol::deposit`、`previewDeposit` | `token` 不满足 `isValidTokenIn`。 |
| `SYInvalidTokenOut(address token)` | `SYBaseUpgradeable.sol::redeem`、`previewRedeem` | `token` 不满足 `isValidTokenOut`。 |
| `SYZeroAddress()` | adapter initializer、`SYBaseUpgradeable.sol::__SYBase_init`、`OutrunL2OracleBackedSYUpgradeable.sol::__L2OracleBackedSY_init`、`setExchangeRateOracle` | 必需的 token、oracle、underlying、stake-manager 或其他配置地址为零地址。具体 initializer 可能先执行自己的地址检查。 |
| `SYZeroDeposit()` | `SYBaseUpgradeable.sol::deposit` | `amountTokenToDeposit == 0`。`previewDeposit` 只做 token 校验，不触发此错误。 |
| `SYZeroRedeem()` | `SYBaseUpgradeable.sol::redeem` | `amountSharesToRedeem == 0`。`previewRedeem` 只做 token 校验，不触发此错误。 |
| `SYZeroSharesOut()` | `SYBaseUpgradeable.sol::deposit` | adapter `_deposit` 返回的 `amountSharesOut` 为零（尘额存款低于汇率量子）。检查位于滑点下限之后：`minSharesOut > 0` 时尘额存款先以 `SYInsufficientSharesOut` 回退，本错误仅在 `minSharesOut == 0` 时可观测。基座在 `_mint` 前统一拒绝，防止铸零份额后尘额本金沉淀下游。`previewDeposit` 只做 token 校验与报价，不触发此错误。 |
| `SYUnauthorizedInternalRedeemer(address caller)` | `SYBaseUpgradeable.sol::redeem` | `burnFromInternalBalance == true` 且 `caller` 不是该 SY 实例 owner 配置的 `trustedRouter`；检查在 adapter `_redeem` 前执行。 |
| `SYInsufficientSharesOut(uint256 actualSharesOut, uint256 requiredSharesOut)` | `SYBaseUpgradeable.sol::deposit` | adapter 返回的 `amountSharesOut` 小于 `minSharesOut`。 |
| `SYInsufficientTokenOut(uint256 actualTokenOut, uint256 requiredTokenOut)` | `SYBaseUpgradeable.sol::redeem` | adapter 返回的 `amountTokenOut` 小于 `minTokenOut`；整个 redeem 原子回滚。 |
| `SYSweepInvalidToken(address token)` | `SYBaseUpgradeable.sol::sweep` | `token == yieldBearingToken()` 或 `token == address(this)`（SY 份额自身），前者保护全部 SY 背书不被抽走，后者阻止 front-run router 的 `burnFromInternalBalance` 待烧份额。 |
| `SYSweepZeroAddress()` | `SYBaseUpgradeable.sol::sweep` | `to == address(0)`。 |
| `SYSweepZeroAmount()` | `SYBaseUpgradeable.sol::sweep` | `amount == 0`。 |
| `InsufficientBacking(uint256 residentBacking, uint256 outstandingShares)` | `SYBaseUpgradeable.sol::_revertIfBackingBelowShares`（经七个覆盖 adapter 的 `exchangeRate` 入口触达，含 `OutrunSlisBNBSYUpgradeable.sol::exchangeRate`、`OutrunL2OracleBackedSYUpgradeable.sol::exchangeRate` 一行覆盖双 L2 子合约） | 适配器自持 yield-bearing-token 余额 < 流通 SY `totalSupply`（resident 背书对账，fail-closed；语义见「名义余额族共享背书对账守卫」段）。 |

### Adapter 专属错误

- `OutrunAaveV3SYUpgradeable.sol::AaveZeroShares()`：`_deposit` 的 Aave scaled-share 换算结果为零时触发。
- `OutrunAsBNBSYUpgradeable` 初始化校验：
  - `InvalidAsBnbMinterAsBnb(address expected, address actual)`：minter 的 `asBnb()` 与配置的 asBNB 不一致。
  - `InvalidAsBnbMinterToken(address expected, address actual)`：minter 的 `token()` 与配置的 slisBNB 不一致。
  - `InvalidYieldProxy()`：minter 返回的 yield proxy 为零地址。
  - `InvalidStakeManager()`：yield proxy 返回的 Lista StakeManager 为零地址；这是 Aster adapter 的声明。
- `OutrunAsBNBSYUpgradeable.sol::_revertOnZeroShares`：
  - `AsBnbMintQueued()`：mint 返回零份额且 `activitiesOnGoing()` 为真，表示 Aster 队列处理中；等待活动完成后重试。
  - `AsBnbMintZeroShares()`：mint 返回零份额且没有进行中的活动，表示真实零产出失败，不按队列分支重试。
- `OutrunAsBNBSYUpgradeable.sol::_deposit` 全量消费守卫：
  - `AsBnbMintIncompleteConsumption(uint256 expectedConsumed, uint256 actualConsumed)`：slisBNB 分支 `balanceAfter != balanceBefore - amountDeposited` 时触发（`_selfBalance` 前后差校验，确认 `IAsBnbMinter.mintAsBnb` 已全量消费输入，否则部分成交残留可被 `SYBaseUpgradeable.sol::sweep` 提取；`expectedConsumed = amountDeposited`，`actualConsumed = balanceBefore - balanceAfter` 为 minter 实际拉取量，参数名与规格共有错位——第二参语义为已消耗量非剩余量），方向为 fail-closed 保守增强
- `OutrunSlisBNBSYUpgradeable`：
  - `InvalidStakeManager()`：初始化时 `convertSnBnbToBnb(1 ether) < 1 ether`；这是 Lista adapter 的同名独立声明，表示 stake-manager 汇率低于平价。
  - `StakeManagerDepositZero()`：原生 BNB 存款前后收到的 slisBNB 余额差为零。
- `OutrunWstETHSYUpgradeable.sol::WstETHStakeFailed()`：`_deposit` NATIVE 腿（经 `WstETH.receive()` 即 `stETH.submit`+`_mint` 的单步质押）低层 call 失败时触发，典型外因为 Lido 质押暂停或接收回退；属外部调用失败的具名包装（与 `RateProviderCallFailed` 的外部调用失败分支同构），非零产出守卫类，零产出兜底由基座 `SYZeroSharesOut()` 承担。
- `OutrunL2OracleBackedSYUpgradeable`（oracle-backed L2 基类，`OutrunL2WstETHSYUpgradeable` / `OutrunL2StakedTokenSYUpgradeable` 经继承；锚点带界语义真源 `docs/spec/yield/oracles-and-integrations.md`「边界」锚点偏差熔断条目）：
  - `RateDeviationExceeded(uint256 newRate, uint256 anchorRate, uint256 allowedBps)`：`OutrunL2OracleBackedSYUpgradeable.sol::exchangeRate`（返回前对 oracle 读数做锚点带界检查，带外即 revert）与 `OutrunL2OracleBackedSYUpgradeable.sol::commitRateAnchor`（带外不推进锚点并 revert）触发；与 `OutrunL2StakedUsdsSYUpgradeable` 的同名错误为不同合约的独立声明（参数形态不同）。该错误经 `OutrunStakingPositionUpgradeable.sol::_currentExchangeRate` 原样透传（同 adapter staleness 错误的 passthrough 通道），`stakeForGenesis` / `previewStake` fail-closed；`redeem` SY 直出不读率，不受影响。另 `ZeroRateAnchor()` 的错误面覆盖两个锚点播种入口：`OutrunL2OracleBackedSYUpgradeable.sol::__L2OracleBackedSY_init` 锚点播种首读为零即 init revert `ZeroRateAnchor()`（fail-fast）；`OutrunL2OracleBackedSYUpgradeable.sol::resetRateAnchor` 无条件把锚点重同步为当前 oracle 读数（读数为零即 revert `ZeroRateAnchor()`，fail-fast——无条件重置永不能播种 anchor==0 并静默停用带检查）。
  - `InvalidRateBreakerParams()`：`OutrunL2OracleBackedSYUpgradeable.sol::setRateBreakerParams` 任一参数越出 sanity 域 `1..10000` 时触发。
  - `RateAnchorOverflow(uint256 reading)`：`OutrunL2OracleBackedSYUpgradeable.sol::__L2OracleBackedSY_init` / `OutrunL2OracleBackedSYUpgradeable.sol::commitRateAnchor` / `OutrunL2OracleBackedSYUpgradeable.sol::resetRateAnchor` 三个锚点写入入口在把 oracle 读数窄化存入 uint96 rateAnchor 之前校验量级，读数超过 `type(uint96).max` 即触发（防御性边界：否则 2^96 整倍数读数窄化为 anchor == 0、经 anchor==0 防御性跳过会静默停用带检查；1e18 量级 conversion rate 在 uint96 下仍有约 11 个数量级裕量）。
- `OutrunL2StakedUsdsSYUpgradeable`（Base Sky sUSDS，`OutrunL2StakedUsdsSYUpgradeable.sol::setRateProvider`/`setMaxDeviationBps`）：
  - `InvalidMaxDeviationBps()`：`OutrunL2StakedUsdsSYUpgradeable.sol::setMaxDeviationBps` 当 `newMaxBps == 0 || newMaxBps > 10000` 触发，允许范围 `1..10000`（`100=1%`）；
  - `RateProviderCallFailed()`：`OutrunL2StakedUsdsSYUpgradeable.sol::initialize` 绑定 `IPSM3.rateProvider()==0`、或 `OutrunL2StakedUsdsSYUpgradeable.sol::exchangeRate` 中 `rateProvider()==0` / `IRateProviderLike.getConversionRate()` try/catch 失败 / `rate==0` 时触发（fail-closed，无 PSM 回退）；
  - `RateDeviationExceeded(uint256 psmRate, uint256 ssrRate, uint256 maxBps)`：`OutrunL2StakedUsdsSYUpgradeable.sol::exchangeRate` 中 `bps = |psmRate - ssrRate| * 10000 / ssrRate > maxDeviationBps` 时触发，`ssrRate = 1 ether * rate / 1e27`，`psmRate = IPSM3.previewSwapExactIn(yieldBearingToken, usds, 1 ether)`，`maxBps = maxDeviationBps()`（默认 `100`）；当 `ssrRate == 0`（`rate∈(0,1e9)` 截断为0）时跳过偏差计算直接返0，由 `OutrunStakingPositionUpgradeable.sol::_currentExchangeRate` 以 `ZeroExchangeRate` fail-closed（与规格字面除零 panic 同为 revert）；
  - `PSM3IncompleteConsumption(uint256 expectedConsumed, uint256 actualConsumed)`：`OutrunL2StakedUsdsSYUpgradeable.sol::_deposit` 非 sUSDS 路径下 `balanceAfter != balanceBefore - amountDeposited` 时触发（差值校验，关闭 sweep 残留；`expectedConsumed = amountDeposited`，`actualConsumed = balanceBefore - balanceAfter` 为 PSM3 实际拉取量，`balanceAfter` 即拉取后剩余）；
  - `SYZeroAddress()`（复用 SYBase 语义）：`OutrunL2StakedUsdsSYUpgradeable.sol::setRateProvider` 当 `newRateProvider == address(0)` 时触发；
  - Owner setters：`OutrunL2StakedUsdsSYUpgradeable.sol::setRateProvider(address)` 与 `OutrunL2StakedUsdsSYUpgradeable.sol::setMaxDeviationBps(uint16)` 均为 `onlyOwner`，前者零地址以 `SYZeroAddress` 回退，后者越界以 `InvalidMaxDeviationBps` 回退。

以上 adapter 级零产出守卫保留用于族特定的诊断（如 Aster 队列区分）；`SYBaseUpgradeable.sol::deposit` 另有基座级 `SYZeroSharesOut()` 兜底，在 `_mint` 前统一拒绝任何 adapter 返回的零份额，未自带守卫的族（如 4626/PSM3/wrap/unwrap 路径的尘额存款）由基座拒绝。

> 以下为实现与规格字面存在微差的已核对行为，方向全部保守/收紧、无一放松（零安全面）：
> - `SYBaseUpgradeable.sol::sweep` 检查顺序：零地址/零额先于 `SYSweepInvalidToken`（`token==address(this)` 且 `to==0` 时实际报 `SYSweepZeroAddress`，非 `InvalidToken`）；错误优先级未定序，不影响安全面
> - `SYBaseUpgradeable.sol::setTrustedRouter` 同值重设不拒绝，emit `SetTrustedRouter(x,x)`（幂等写入，零安全面）
> - `OutrunOFTUpgradeable.sol::_removeDust` 本地 `unchecked` 覆写（`(_amountLD / DCR) * DCR`，数学等价于 `OFTCoreUpgradeable` 检查版，`floor(a/r)*r ≤ a` 恒成立）
> - 继承 `InvalidLocalDecimals`（`OFTCoreUpgradeable` 要求 `localDecimals ≥ 6`，本仓库 18-dec 部署不可达，仅继承暴露）
> - `OutrunOFTUpgradeable.sol` `window==0` 早退跳过显式 `_removeDust`（返回值已是 DCR 倍数，重施为 no-op；`OutrunOFTUpgradeable.sol::_credit` 注释自证）
> - `PSM3IncompleteConsumption` 第二参命名错位（`actualRemaining` 实载已消耗差值 `balanceBefore - balanceAfter`，规格与代码共有，语义以实现为准）
> - `OutrunExchangeOracleAdapter.sol::rawDecimals` public getter 暴露（构造期捕获 `AggregatorInterface.decimals()`，仅读视图）
> - `OutrunL2StakedUsdsSYUpgradeable.sol::maxDeviationBps()` 0→100 映射（storage 0 时 getter 返 100 默认，`initialize` 后恒为 100 不可达，仅为未配置态兜底）
> - `OutrunRouter.sol` 注册表不再以显式代码门对 `SY`/`SP` 缺代码 fail-closed（allowlisting 为 owner 治理职责）；下游调用与绑定复读仍回退（对无代码地址以底层调用/解码错误回退，SY selfdestruct 后仍在下游回退）

- 名义余额族共享背书对账守卫（fail-closed）：实现下沉为 `SYBaseUpgradeable` 的共享内部断言 `SYBaseUpgradeable.sol::_revertIfBackingBelowShares`，由各覆盖 adapter 在 `exchangeRate` 入口调用，`InsufficientBacking(uint256 residentBacking, uint256 outstandingShares)` 随之声明于基类（error 名与签名不变，声明点移至基类，外部可观察行为不变；`OutrunL2StakedUsdsSYUpgradeable` 收敛为调用共享断言，删除本地 error 与内联检查）。要求适配器自持 yield-bearing-token 余额（resident backing）≥ 流通 SY `totalSupply`，不足即 revert。依据：SYBase 单位约定 1 SY ≡ 1 yield-bearing-token unit（`SYBaseUpgradeable.sol::_deposit` NatSpec），且 `SYBaseUpgradeable.sol::sweep` 已把 yield-bearing token 钉死为不可抽走的份额背书，故该族自持余额即流通份额的全额背书。效果：SP 侧全部换算经单一率读取点 `OutrunStakingPositionUpgradeable.sol::_currentExchangeRate` 汇入 `exchangeRate`，断言触发时 `OutrunStakingPositionUpgradeable.sol::stakeForGenesis`/`previewStake` 全部 fail-closed（消费面口径同 `docs/spec/position/accounting.md` §11.1 的 `ZeroExchangeRate` 行）——resident 背书跌破流通份额时面值铸出路径自动冻结，不依赖 owner 响应；`redeem` 不读汇率（债务按 syRedeemed/syStaked 比例计算，见 `docs/spec/position/accounting.md` §11 的 `ZeroExchangeRate` 消费面），守卫触发时仍可用，为有意的退出通道保留而非守卫遗漏。适用范围（显式枚举，七成员）：Sky L2 sUSDS（`OutrunL2StakedUsdsSYUpgradeable`，其背书托管与率换算均经外部 L2 协议）、主网名义 1:1 三族（`OutrunWstETHSYUpgradeable`、`OutrunStakedUsdsSYUpgradeable`、`OutrunStakedUSDeSYUpgradeable`）、`OutrunSlisBNBSYUpgradeable`（slisBNB 名义 1:1，`OutrunSlisBNBSYUpgradeable.sol::exchangeRate` 入口调用共享断言）、`OutrunAsBNBSYUpgradeable`（asBNB 名义 1:1，`OutrunAsBNBSYUpgradeable.sol::exchangeRate` 入口调用共享断言）与 L2 oracle-backed 1:1 变体（`OutrunL2OracleBackedSYUpgradeable.sol::exchangeRate` 首行守卫一行覆盖继承它的 `OutrunL2WstETHSYUpgradeable`、`OutrunL2StakedTokenSYUpgradeable`）均在守卫覆盖内；scaled-share 域（如 Aave aToken 族，其余额随流动性指数增长、不等于背书计量）不满足判据，仍显式排除、不在枚举之列。WeETH v1 未接入、不布线。前置条件：yield-bearing token 为标准 token（非 fee-on-transfer），名义转账额=实收额，与既有名义记账前设同源。诚实边界：守卫不恢复已失背书，只阻断续铸；快照语义下外部 spender 若能临时把资金「停车」回适配器可瞬时通过断言（该面的根治在 `_redeem` 逐笔精确授权，见统一规则）；适配器率源仍为外部合约，守卫不校验率值本身。

### 事件与原生币接收边界

- `SYBaseUpgradeable.sol::deposit` 每笔成功存款在成功路径末端无条件发出 `Deposit(address indexed caller, address indexed receiver, address indexed tokenIn, uint256 amountDeposited, uint256 amountSyOut)`（声明于 `IStandardizedYield.sol`）：`caller` 为 `msg.sender`，`tokenIn` 已经入口 `isValidTokenIn` 校验（非法回退 `SYInvalidTokenIn`），`amountDeposited` 为 `msg.sender` 出资的输入数量，`amountSyOut` 为 `_mint(receiver, amountSharesOut)` 铸出的 SY 数量；emit 位于全部守卫（`minSharesOut`/`SYZeroSharesOut`）与铸币之后，观测到该事件即代表 deposit 完整落账（份额已铸给 `receiver`）。
- `SYBaseUpgradeable.sol::redeem` 每笔成功赎回在成功路径末端无条件发出 `Redeem(address indexed caller, address indexed receiver, address indexed tokenOut, uint256 amountSyToRedeem, uint256 amountTokenOut)`（声明于 `IStandardizedYield.sol`）：`caller` 为 `msg.sender`，`tokenOut` 已经入口 `isValidTokenOut` 校验（非法回退 `SYInvalidTokenOut`），`amountSyToRedeem` 为本轮烧毁的 SY 数量（直兑路径烧 `msg.sender`、`burnFromInternalBalance=true` 路径烧合约自身，结算顺序与授权面见「统一规则」），`amountTokenOut` 为 `_redeem` 实际交付数量；emit 位于 `_redeem`、`_burn` 与 `minTokenOut` 滑点守卫之后，观测到该事件即代表 redeem 完整落账。两事件各含三个 indexed topic（caller/receiver/tokenIn 或 tokenOut），数量字段不加 indexed 落在 data；全部 adapter 经 `SYBaseUpgradeable.sol` 继承同一 emit 点，adapter 自身不声明生命周期事件（adapter 层仅有本节已列的 setter/锚点事件）。
- `OutrunL2OracleBackedSYUpgradeable.sol::setExchangeRateOracle` 更新 oracle 后发出 `SetExchangeRateOracle(address indexed oldOracle, address indexed newOracle)`；该事件只适用于继承 oracle-backed 基类的 L2 adapter。换指针保留已存 rate anchor（换入 oracle 仍须对旧锚点通过带界；owner 采纳量级合法不同的源走显式 `resetRateAnchor`）；仍 instant、onlyOwner、无 timelock。
- `OutrunL2OracleBackedSYUpgradeable.sol::commitRateAnchor`（permissionless）带内推进锚点后发出 `RateAnchorCommitted(uint256 indexed anchor, uint256 timestamp)`；`OutrunL2OracleBackedSYUpgradeable.sol::resetRateAnchor`（onlyOwner）把锚点重同步为当前 oracle 读数后发出 `RateAnchorReset(uint256 indexed oldAnchor, uint256 indexed newAnchor)`（恢复路径，owner 只能采纳 feed 当前读数、不能注入任意值）；`OutrunL2OracleBackedSYUpgradeable.sol::setRateBreakerParams`（onlyOwner，逐参数域 `1..10000`，越界 revert `InvalidRateBreakerParams`）更新熔断参数后发出 `SetRateBreakerParams(uint16 maxDropBps, uint16 riseBpsPerHour, uint16 maxRiseCapBps)`（保持全参数不加 indexed：三个 uint16 作为 topic 只增日志成本、无过滤价值）。锚点带界语义、默认值（`maxDropBps` 10 / `riseBpsPerHour` 5 / `maxRiseCapBps` 200）与部署校准真源见 `docs/spec/yield/oracles-and-integrations.md`「边界」锚点偏差熔断条目。
- `OutrunL2StakedUsdsSYUpgradeable.sol::setRateProvider`（onlyOwner）换 SSR RateProvider 后发出 `RateProviderSet(address indexed oldRateProvider, address indexed newRateProvider)`；`OutrunL2StakedUsdsSYUpgradeable.sol::setMaxDeviationBps`（onlyOwner，值域 `1..10000`，越界 revert `InvalidMaxDeviationBps`）更新偏差界后发出 `MaxDeviationBpsSet(uint16 oldMaxDeviationBps, uint16 newMaxDeviationBps)`（uint16 不加 indexed，对齐 `SetRateBreakerParams` 的事件成本理由）。Sky L2 族不继承 oracle-backed 基类、无 `SetExchangeRateOracle` 家族事件，两事件即该族专属治理参数变更（换源/调参）的唯一事件观测面，与 oracle-backed 族换源/调参事件同构承载 (old,new)；监控消费口径见 `docs/deployment.md`「L2 oracle-backed SY 部署校验清单」监控告警（率漂移告警条）。
- `SYBaseUpgradeable.sol::setTrustedRouter` 由 owner 更新 `trustedRouter` 后发出 `SetTrustedRouter(address indexed oldRouter, address indexed newRouter)`；零地址表示撤销并关闭 `burnFromInternalBalance=true` 路径，仅 `trustedRouter()` 返回的地址可调用 `SYBaseUpgradeable.sol::redeem(..., burnFromInternalBalance=true)`（见 `SYBaseUpgradeable.sol::setTrustedRouter` 与 `::redeem`），其余调用方传入 `true` 回退 `SYUnauthorizedInternalRedeemer(address caller)`；每个官方 SY 需由 owner 先 `setTrustedRouter(OUTRUN_ROUTER)` 并核对事件与 `trustedRouter()` 读取值后再开放 `OutrunRouter.sol::redeemSyToToken`，轮换时先对每个 SY 设置新 router 并核对再停用旧入口（见 `docs/spec/router/router-and-user-flows.md` §3 与 `docs/spec/access-control.md` SY 赎回授权面）。
- `SYBaseUpgradeable.sol::sweep` 由 owner 救援滞留资产后发出 `Sweep(address indexed token, address indexed to, uint256 amount)`；`token == address(0)` 时表示原生 ETH/BNB（NATIVE sentinel，与 `TokenHelper` 一致），`yieldBearingToken()` 与 `address(this)` 已在入口以 `SYSweepInvalidToken` 阻断，分别保护份额背书与 router 待烧份额；`to == address(0)` / `amount == 0` 分别以 `SYSweepZeroAddress` / `SYSweepZeroAmount` 回退，仅 `onlyOwner` 且 `nonReentrant` 可达（见 `SYBaseUpgradeable.sol::sweep`）。
- `SYBaseUpgradeable.sol::receive()` 接收原生币，但函数本身没有业务分支或转出逻辑。误转原生币可能形成合约余额，集成方应将其视为可能滞留的边界，不把转账成功当作 deposit 成功。
- `NativeAmountMismatch`、`NativeTransferFailed` 以及外部协议 revert 仍需在集成层保留独立分支；它们不是本节列出的 SY/adapter 自定义错误。

## Aave aToken 接口消费面

`OutrunAaveV3SYUpgradeable` 通过本地 `IAToken` 接口（`src/integrations/aave/interfaces/IAToken.sol`）消费以下 aToken 成员：

- `UNDERLYING_ASSET_ADDRESS()`：在 `initialize` 中绑定 adapter 的 underlying（`OutrunAaveV3SYUpgradeable.sol::initialize`）
- `scaledBalanceOf(user)`：在 underlying 存款路径中按流动性指数前后差值计量 scaled shares（`OutrunAaveV3SYUpgradeable.sol::_deposit`）

deposit / redeem 的份额换算公式与 half-up / floor 舍入方向以 `docs/spec/common-foundations.md` 单位模型的「ray 域换算（Aave 流动性指数）」小节为准（引用不复述）；该小节与上表 `OutrunAaveV3SYUpgradeable` 行 Exchange Rate Source 列的 `IAaveV3Pool.getReserveNormalizedIncome(underlying) / 1e9`（ray→wad 派生：1e27 域指数 ÷ 1e9 = 1e18 域汇率；整数除floor，余数<1e9 Ray即<1 wei/1e18且相对<1e-18，偏差保守且可忽略，canonical asset -> SY down/up 内联公式在 SP 侧均已无消费方（见该节）；半入仅为 ray 域上的不同舍入策略（见 ray 域换算节），此处 floor 不依赖外部协调、仅取保守方向故不采纳半入，见`OutrunAaveV3SYUpgradeable.sol::exchangeRate`）互为对照。

## Aster 接口消费面

`OutrunAsBNBSYUpgradeable` 消费以下接口成员（Aster 集成位于 `src/integrations/aster/interfaces/`，Lista 换算接口位于 `src/integrations/lista/interfaces/`）：

- `IAsBnbMinter.asBnb()` / `token()` / `yieldProxy()`：initialize 期经 `OutrunAsBNBSYUpgradeable.sol::_validateMinter` 做 minter 绑定校验——`asBnb()` 绑定 yield-bearing token、`token()` 绑定 slisBNB 支持集、`yieldProxy()` 抵达 Lista stake manager（`OutrunAsBNBSYUpgradeable.sol::initialize`）
- `IAsBnbMinter.mintAsBnb()`（slisBNB 重载）/ `mintAsBnb()` payable（native BNB 重载）：存款主路径的铸造调用——native 分支以 call value 转入 BNB，slisBNB 分支先经逐笔精确 `_safeApprove` 授权本次拉取额再传入数量，`_deposit` 以 `_selfBalance` 前后差 `balanceAfter != balanceBefore - amountDeposited` 校验全量消费（`AsBnbMintIncompleteConsumption`，见上节错误面，方向 fail-closed）；零返回值进入 `_revertOnZeroShares` 的区分逻辑（`OutrunAsBNBSYUpgradeable.sol::_deposit`）
- `IYieldProxy.stakeManager()`：initialize 期从校验过的 yieldProxy 取得 Lista StakeManager 地址写入 storage，供 `exchangeRate()` 与 `_previewDeposit` 换算路径使用
- `IYieldProxy.activitiesOnGoing()`：mint 返回零份额时区分「Aster 队列处理中（可重试）」与「真实零产出失败」（`OutrunAsBNBSYUpgradeable.sol::_revertOnZeroShares`）
- `IListaStakeManager.convertSnBnbToBnb` / `convertBnbToSnBnb`：lista 包接口，与上表 SlisBNB 行所引同一 `IListaStakeManager`；Aster adapter 在 initialize 期经 `IAsBnbMinter.yieldProxy()` → `IYieldProxy.stakeManager()` 校验并取得其实例；分别用于 `exchangeRate()` 的第二跳换算与 native BNB 存款预览的第一跳换算

本文档的逐成员消费面小节为按需补记（现仅 Aave 与 Aster）；小节未覆盖的被消费成员以 Adapter Evidence Matrix 各行点名为准。
